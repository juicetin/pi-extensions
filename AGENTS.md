# Agent instructions

This repository uses Beads (`bd`) for durable task tracking. Run `bd prime` when session context is missing or stale.

The generated Claude, Codex, and agent-skill integrations load Beads context. They are advisory tracking support. They do not enforce delivery cadence, seal scope, block mutations, validate receipts, or launch independent review.

## Repository workflow

`main` is integration-only. Do not implement directly in the root checkout.

Each implementation changeset uses:

> one leaf bead = one `bd-<id>` branch = one `bd worktree create` worktree = one reviewable PR

Before changing files:

```bash
bd where
bd context
bd dolt remote list
bd show <id>
bd update <id> --claim
bd worktree create .worktrees/bd-<id> --branch bd-<id>
```

Rules:

- Use `bd` for shared tasks, dependencies, blockers, and handoff state.
- Do not use markdown TODO files as the durable task source of truth.
- Do not use raw `git worktree add`; use `bd worktree create`.
- Do not create a feature branch in the root checkout.
- Preserve dirty root files. Do not move, clean, stash, or discard another session's changes.
- Keep one bead and one reviewable concern per worktree.
- Cross-repository work must use a leaf bead, `bd-<id>` branch, `bd worktree create` worktree, and PR in the repository that owns the changed files. Do not represent another repository's implementation with a pi-extensions bead or worktree.
- Create a new owner-repository leaf before expanding into a different repository, domain, trust boundary, dependency, or acceptance criterion.
- Do not treat a commit or push as delivered. Record the correctly based PR and verification evidence.

## Embedded Dolt and synchronization

This repository uses embedded Dolt. Do not set Beads server-mode environment variables.

For S3 synchronization:

```bash
AWS_PROFILE=dev AWS_DEFAULT_REGION=ap-southeast-2 bd dolt pull
AWS_PROFILE=dev AWS_DEFAULT_REGION=ap-southeast-2 bd dolt push
```

Run `bd ready --json` to find unblocked work. Runtime databases, locks, backups, credentials, redirects, and export state remain local and ignored.

For a fresh clone:

```bash
chmod 700 .beads
git config beads.role contributor
bd bootstrap --dry-run
AWS_PROFILE=dev AWS_DEFAULT_REGION=ap-southeast-2 bd bootstrap --yes
```

Use `maintainer` instead of `contributor` only when that role is assigned. The permission step prevents local Dolt and credential state from inheriting a group-writable checkout umask.

## Generated hook behavior

The tracked Beads Git hooks are generated by Beads 1.1.0.

- Trigger: `bd` is unavailable. Behavior: the hook does not run. Impact: Git proceeds without Beads hook processing.
- Trigger: a hook exceeds `BEADS_HOOK_TIMEOUT` (default 300 seconds) or the database is not initialized. Behavior: the hook prints an error and allows Git to continue.
- Other nonzero hook errors fail the Git operation.

Git remains available during tracker startup or timeout so source recovery is not coupled to local tracker health. This does not count as successful Beads synchronization. Before completion, run the explicit `bd` status/comment and `bd dolt push` commands below and treat any failure as blocking.

## Completion checklist

Before closing a leaf:

1. Re-read `bd show <id>` and verify every acceptance criterion.
2. Confirm the cwd is `.worktrees/bd-<id>` and the branch is `bd-<id>`.
3. Run the relevant tests, type checks, and security checks.
4. Commit the leaf and push its branch.
5. Open a PR with the intended head and base.
6. Add a Beads comment with the PR and verification evidence.
7. Close or update the bead only when its delivery contract is satisfied.
8. Synchronize Beads and code:

```bash
AWS_PROFILE=dev AWS_DEFAULT_REGION=ap-southeast-2 bd dolt push
git push
git status
```

A failed push or unverified PR is a blocker. Do not silently downgrade completion to a local commit.
